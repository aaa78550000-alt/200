# 視覺策略：不再做「AI 罐頭 UI」

## 為什麼要重新探索
先前產出的 PetOS 圖面色調大致合適，但有太多重複的圓角卡、制式 Dashboard 和不可信的繁體中文字排版。使用者明確不滿意，不要逐像素複製圖面。我們保留「專業、有溫度、毛孩照片突出」的品牌意圖，但把資訊結構和構圖重新設計。

## 品牌句
「店務有秩序，照顧更有溫度。」（暫用，並非確認商標）

## 第一輪設計探索：三種不同構圖，不是三套顏色
### A：Studio Ledger — 管理效率導向
- 針對店長／櫃檯的工作畫面：編輯式排版、清楚的分隔線、行程時間軸、局部緊湊列表。摘要少而精。
- 今日工作卡片輕量；密度適中，主要時間與任務一眼可見。
- 尤其適合桌面排程與多預約管理。

### B：Pet Dossier — 毛孩個人檔案導向
- 針對美容師的工作場景：高辨識毛孩照片 + 像照護檔案的資訊層級；重要警示比美觀更優先。
- 深淺色塊節制使用；詳細資訊像編輯式檔案，而不是一堆等高卡。
- 尤其適合手機毛孩檔案和服務記錄。

### C：Quiet Concierge — 飼主簡潔預約導向
- 針對飼主：清楚服務選項、單一步驟任務、固定底部下一步；不夾帶複雜後台元素。
- 有舒適的留白、漂亮的照片與進度提示，但不讓 CTA 與價格藏起來。
- 適合飼主四步預約。

不是要三套分裂的品牌：A/B/C 使用共同 token 與品牌識別，但按工作場景呈現不同密度。Agent 需先產出 3 個概念（可以是文字+線框），自主挑適合各畫面的構圖；記錄選擇理由和捨棄項（見 `DESIGN_EXPLORATION.md`）。

## 共通視覺語言
- Calm Studio：暖白、青綠、深灰；毛孩照片提供溫度，不靠腳印圖樣當背景。
- 70% 專業工具、20% 溫和生活感、10% 品牌識別，只是方向不是計量比例。
- 不要一律中央對齊的大照片：毛孩檔案可能大，預約列表只要 52px 識別頭像。
- 優先使用高品質、合法可用的毛孩照片，統一裁切、替代文字與載入 fallback；不讓照片變成跨店隱私資料。
- 不預設每頁都有 3~5 個 KPI 卡、大漸層、陰影、星星火花、圓形彩色 icon，除非有明確用途。
- 每一個畫面都應明確指出「當前最重要的一件事」及「第一視線會看到什麼」。

## 設計哲學 / skill 對應
- distinctive-ai-design：探索→定義→真實截圖審查→刪減。僅首次建立方向或大幅重設計需要三方向探索。
- petos-ui-design：本專案不可打破的功能資訊與 Design Token，合理元件組織。
- petos-visual-qa：固定尺寸瀏覽器驗收，不用「看起來應該可以」取代證據。
- landing-page-design 只適合後來的行銷官網；不把行銷頁動態套進店家操作介面。

## 評審問題（必須回答）
1. 第一眼看得到今天／這張卡最重要的操作嗎？
2. 寵物名字／照片／時間／狀態是否有清楚主從？
3. 哪些卡片或說明其實可刪掉？
4. 切到 390px 後仍有合理密度與點擊面積嗎？
5. 圖片載入失敗、字比較長、資料空值時仍好用嗎？
6. 和 1440px 桌面相比，資訊不是只等比例縮放？
7. 美容注意事項是不是在需要照護的那個時刻出現？

## 圖像與動態
- 動態要說明狀態：按鈕 100~150ms、卡展開約 180~250ms、抽屜約 200~300ms，支援 reduced motion。
- 正式後台避免視差、長入場、持續漂浮；行銷展示與產品操作採不同動畫規則。
- screenshot 評審初期最多 2 輪，每輪修 1~3 個最大問題；若沒有改善則改 brief，不能無限追評分。
