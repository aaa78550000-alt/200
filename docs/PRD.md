# 產品需求 PRD｜PetOS

## 問題及目標
店家用 LINE 訊息、紙本或多個 App 處理預約、契約、毛孩注意事項、美容進度與帳款，容易重複輸入、遺漏提醒、產生時段衝突。PetOS 要讓一次服務相關資料集中，員工能在手機快速操作，店長能在桌面掌握整天工作，飼主可自行預約。

## 客群、使用者與權限
- **Owner**：店主，店務全部管理、服務定價、員工、財務、重要設定。
- **Manager**：店長，預約／人員／付款管理，部分財務設定需授權。
- **Groomer**：美容師，看自己與店家已授權的預約、照護、完工與毛孩注意事項；不看不必要的財務或全店敏感資料。
- **Receptionist**：櫃檯，預約、報到、收款及交接，無權限更動員工角色或店家訂閱。
- **Customer**：飼主，自有毛孩與預約、簽約、自己被授權的服務紀錄。
- **Platform Admin**：平台管理員，最小權限與被記錄的支援操作，不任意瀏覽飼主個資。
- 一人可兼店主與美容師：角色／membership 與 staff profile 分離。各 shop 資料隔離。

## 毛孩檔案（核心差異）
- 主要資訊：可上傳寵物頭像、名字、物種、品種、性別、生日／估計年齡、最近體重與測量日期。
- 詳細資訊：毛色、是否結紮、晶片號碼（選填且權限限制）、體重歷史、照護注意事項、行為習慣、洗護產品偏好、修剪要求、預估時間。
- 注意事項：皮膚敏感、對特定用品不適、怕吹風機、抗拒剪指甲、可能咬人等。標示來源（飼主提供／美容師觀察）、觀察／更新日期，不當成獸醫診斷。
- 資料關聯：一個 owner 多隻 pets；每隻 pet 多次 appointments、care records、照片、體重記錄與服務歷史。
- 照片類別：頭像、美容前、美容後、照護／事件照片；私有 Storage，權限簽章 URL；列表縮圖固定比例。
- 逐步建檔：首次只要求姓名、物種、主要飼主及預約必要資訊，詳細健康資料後續補齊，不使用超長必填表單。

## 店家日常最重要任務
1. 搜尋飼主電話、毛孩名字、品種，辨識同名毛孩。
2. 熟客快速新預約：帶入飼主、毛孩、常用服務／服務工時（仍需確認）。
3. 時間排程：美容師服務資格、服務時間、緩衝、休假、店休、資源容量，修改時做衝突檢查。
4. 預約詳情：同一上下文能報到、檢視注意事項、記錄美容、完工、通知、收款與交接。
5. 財務：服務金額與付款是不同狀態，退款與例外都留歷史。

## 飼主端
四步：選服務→選時段→毛孩／身分資料→確認送出。完整價格或「起」的估價口徑清楚；待確認不顯示成已預約成功；首次只收必要資料；熟客完成安全驗證後才帶入資料。

## 不在 M0／核心 MVP 的內容
完整人資、GPS 打卡、正式線上收款、醫療診斷、AI 自動同意額外收費、跨店共享健康病歷、複雜 B2C 電商。

## 價值與待驗證假設
熟客建立預約、尋找毛孩與正常完工速度應可實測改善；時間目標（熟客新增／正常完工各 30 秒內）只是產品設計假設。對店家真實付費、留存、開發成本需另外做訪談與驗證。
