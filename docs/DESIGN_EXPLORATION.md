## 0. 真實任務與情境（決定構圖的依據）

| 畫面 | 主要使用者 | 使用時刻 | 第一視線必須看到 |
|---|---|---|---|

## 1. 三個概念（構圖與資訊組織不同，不是換色）

### 概念 A：Studio Ledger（店務帳簿）
隱喻：櫃檯上那本手寫的「日記帳」。一條**時間脊柱**由上而下，每一列是一筆預約，像帳簿的一行。

```
 Mobile 390                         Desktop 1440
┌──────────────────────┐   ┌────────┬───────────────────────────┬──────────────┐
│ 10/28 週三   今日工作 🔔│   │ PetOS  │ 10月28日 週三      ＋新增預約 │ 焦點：Lucky   │
│ 8 筆 · 服務中1 · 待接回1 │   │ 今日    │──────────────────────────│ 待接回        │
│──────────────────────│   │ 行事曆  │ 現在 15:10 ───────────────│ 應收 NT$650   │
│ 14:00 │[◼] Coco    服務中│   │ 毛孩    │ 14:00 │ Coco  洗澡＋修剪 服務中 │ [收款][交接]  │
│       │ 洗澡＋修剪·Amy    │   │        │ 13:30 │ Lucky 洗澡＋梳毛 待接回 │ 注意事項…     │
│ 13:30 │[◼] Lucky   待接回│   │        │ 15:30 │ 奶茶  基礎洗澡   已確認 │ 事件紀錄…     │
│ 15:30 │[◼] 奶茶    已確認│   │        │ …                           │              │
└──────────────────────┘   └────────┴───────────────────────────┴──────────────┘
```
- 摘要只是一行文字＋可點的篩選，不是 KPI 卡。
- 列與列以髮絲線分隔，不用卡片；時間用等寬數字（Geist tabular）對齊成一條欄。
- 桌面是 **master–detail**：左帳簿、右常駐焦點面板（= 預約詳情抽屜）。
- 優點：密度高、掃描快、和行事曆共用時間語言。缺點：毛孩溫度較弱，手機上照護資訊不夠突出。

### 概念 B：Pet Dossier（毛孩照護檔案）
隱喻：寵物醫院的病歷夾＋貼在美容台旁的「照護便條」。以**毛孩**為主角，資訊像編號的檔案章節，注意事項像貼在邊緣的批註（marginalia）。

```
 Mobile 390                         Desktop 1440（今日：店內看板）
┌──────────────────────┐   ┌────────┬───────────────────────────────────────┐
│ ← 毛孩檔案        ⋯   │   │        │ 店內毛孩                               │
│ ┌────┐ Coco          │   │        │ ┌──────┐ ┌──────┐ ┌──────┐             │
│ │96px│ 貴賓·母·6歲   │   │        │ │ 照片 │ │ 照片 │ │ 照片 │  ← 照片看板  │
│ └────┘ 林小姐 →      │   │        │ │Coco  │ │Lucky │ │奶茶  │             │
│ 4.8 kg · 10/14 量測   │   │        │ │服務中│ │待接回│ │未到店│             │
│▌皮膚敏感  飼主提供 9/2 │   │        │ └──────┘ └──────┘ └──────┘             │
│▌怕吹風機  Amy觀察 10/14│   │        │ 稍後 ───────────────────────────────── │
│ 01 概覽 02 紀錄 03 照護 │   │        │ 16:30 吐司 · 17:00 布丁                 │
└──────────────────────┘   └────────┴───────────────────────────────────────┘
```
- 注意事項用左側赭色細條（批註），附來源與日期。
- 今日畫面以「店內毛孩看板」（照片磚）表達實體空間。
- 優點：毛孩辨識度最高，美容師情境最好用；有溫度。缺點：照片磚在今日工作裡占面積大、時間順序弱；桌面看板在 8 筆以上時會變成一堆等高卡（正是使用者討厭的）。

### 概念 C：Quiet Concierge（安靜的接待員）
隱喻：一位一次只問你一件事的接待員。**單一焦點**，每屏只有一個主要任務，固定底部的一個行動。

```
 Mobile 390（今日：下一件事）         Desktop 1440（飼主預約）
┌──────────────────────┐   ┌──────────────────────────────────────────────┐
│ 下一件事               │   │ 靜室寵物美容                                  │
│ ┌──────────────────┐ │   │ ①服務 ②時段 ③毛孩 ④確認                       │
│ │ Lucky 待接回       │ │   │ ┌──────────────────────┐ ┌──────────────┐ │
│ │ 應收 NT$650        │ │   │ │ ○ 基礎洗澡 NT$700 起  │ │ 你的預約摘要  │ │
│ │ [ 收款並交接 ]     │ │   │ │ ● 洗澡＋修剪 NT$900起 │ │ 洗澡＋修剪    │ │
│ └──────────────────┘ │   │ │ ○ 精緻造型 …          │ │ 120 分鐘      │ │
│ 之後：奶茶 15:30 …     │   │ └──────────────────────┘ └──────────────┘ │
│ [   下一步   ]  固定底部 │   │                               [ 下一步 ]   │
└──────────────────────┘   └──────────────────────────────────────────────┘
```
- 大量留白、大字、一個 CTA。
- 優點：飼主端最清楚、不會迷路。缺點：對店員太慢——今日有 8 筆時只看到一件事，需要一直往下滑；不適合後台密度。

## 3. 選擇（D-03）

**一個品牌、三種密度**，依畫面任務分配：

| 畫面 | 採用 | 理由 |
|---|---|---|
| 今日工作 | **A** 為骨架 ＋ B 的「店內」分組 | 時間脊柱掃描最快；但把「店內（已報到／服務中／待接回）」放在最上方獨立一段，回應櫃檯「現在誰在店裡」的實體問題。桌面採 master–detail，右側常駐詳情面板。 |
| 毛孩檔案 | **B** | 檔案式章節＋邊緣批註式注意事項；手機第一屏一定看得到體重與注意事項。 |
| 行事曆 | **A** | 美容師欄 × 時間軸，與今日帳簿共用等寬時間欄語言。 |
| 預約詳情 | **A 的結構 ＋ B 的照護批註** | 頂部識別＋注意事項（B），下方四條獨立狀態列與單一主要動作（A）。 |
| 飼主預約 | **C** | 單一步驟、固定底部 CTA；桌面 2 欄（步驟＋摘要）。 |

**捨棄**：
- B 的「今日照片看板」整頁版本 → 8 筆以上變等高卡牆；只保留為「店內」分組中較大的頭像。
- C 的「下一件事」大卡作為今日主畫面 → 對店員太慢；改成桌面右側焦點面板（A）的預設內容。
- 深色側欄 → 太像一般 SaaS 模板；改用與畫布同色、以髮絲線分隔的淺側欄。
- 圓形頭像 → 改用 **12px 圓角方形「證件照」頭像**，呼應 Dossier 隱喻，也和一般 SaaS 的圓頭像區隔。

## 4. 執行 Brief

> **使用者與任務**：台灣中小型寵物美容店的櫃檯／店長／美容師在手機與桌面處理一天的預約；飼主在手機申請預約。
> **目標感受**：像一間安靜、有秩序的工作室——專業工具為主，毛孩照片帶來溫度。
> **核心隱喻**：店務帳簿（時間脊柱）＋ 毛孩照護檔案（證件照＋邊緣批註）。
> **構圖與層級**：等寬時間欄 → 證件照頭像 → 毛孩名（最大字）→ 服務／美容師（次要）→ 狀態標籤（文字＋形狀）。分組靠髮絲線與留白，不靠卡片。每屏只有一個 primary CTA。
> **色彩**：暖白畫布、白色工作面、深墨文字；青綠只給主要動作與「服務中」；赭色只給「需要注意」與「待確認」；綠色只給「完成可接回」。其他一律中性。
> **字體**：Noto Sans TC（中文）＋ Geist（英數、等寬時間數字 `tabular-nums`）。名字 17–18/700，正文 16，輔助 14，註解 12（只給來源與日期）。
> **關鍵互動**：點列 → 詳情（桌面右側面板／手機全螢幕面板）；狀態主動作直接在詳情底部；完成美容在同一面板內展開 finish_review；行事曆點空白 → 帶入時間與美容師的新增預約。
> **避免**：KPI 卡排、漸層、陰影堆疊、腳印圖案、彩色圓 icon、卡中卡、所有區塊等高。
> **第一版範圍**：五個核心畫面＋毛孩搜尋列表＋新增預約面板＋ DEMO 工具列（重設、模擬離線、模擬時段被搶、切換角色）。

| `--danger` | #B74848 | 同 | 白底 5.3:1 |
