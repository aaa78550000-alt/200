# 精確 Screen Blueprint（實作依據）

所有尺寸為設計初值，Agent 應以真實畫面實測後微調，並記錄偏差原因。五頁須有 desktop/mobile 版本，不得只縮放。

## 01 今日工作 `/app/today`
使用者：櫃檯、店長、美容師｜任務：快速找到下一筆工作，完成狀態切換。
- Mobile 390：安全區＋16px 左右內距；Header 日期、今日工作、通知；下方一排輕量摘要（今日預約、服務中、待接回；不用排滿圖表）；主內容「現在進行／接下來的預約」。
- AppointmentRow 頭像 52px 左，中間毛孩名（16~18px bold）、服務及美容師（14px），時間/狀態可見。服務中可在展開時顯示一個主要 CTA「完成美容」，不要每行同時 4 個大按鈕。
- Desktop 1440：左側 224px 導航、主頁日期＋新增預約、主列表／側邊輔助；不要大面積無關圖表。
- State：空列表應顯示「今天沒有預約」及「新增預約」；讀取失敗有重試；搜尋和篩選後空結果另有文字。
- 點卡→開預約詳情；點快速 CTA→該狀態對應操作；返回後卡片狀態和數字同步。

## 02 毛孩檔案 `/app/pets/:id`
任務：一眼認出毛孩、看見照護提醒、快速預約。
- Mobile：Header 返回＋操作；Hero 有頭像 96px、毛孩名 24px、品種/性別/年齡；在第一屏顯示最近體重（kg＋測量日期）、重要注意事項（來源＋更新日期）；次級分頁「概覽／美容紀錄／照護資訊／相簿／會員」。
- Desktop：照片與概要置左約 320px，右側主要內容為注意事項及歷史；密度適中，不要將所有信息塞滿左欄。
- 基本欄位：頭像、名字、物種、品種、性別、生日/估計年齡、體重歷史、結紮、毛色、晶片（選填）。注意事項：皮膚敏感、藥物／洗護偏好、行為問題、來源/日期。
- 照片篩選美容前／美容後／照護；來源標記；點擊大圖；空值不顯示假的評級或診斷。
- CTA「新增預約」帶入 pet id；編輯為次要操作；新建毛孩不用一次填全部欄位。

## 03 預約行事曆 `/app/calendar`
任務：看時間資源、發現衝突、快速新增。
- Desktop：左側導航＋日期、日／週切換；主時間軸按美容師欄列展示，縱軸至少能看 09:00、10:00、11:00 等時間；每筆預約方塊位置與高度對應開始／結束時間；緩衝、休假、店休日清楚顯示。
- Mobile：日期切換、今日時間軸／列表、員工篩選，不硬縮桌面多欄。
- 空白時段點擊→新建並預填時間＋美容師；點已有區塊→側欄詳情；改期或拖拉需二次確認並後端驗證，不得只移動 DOM 就算成功。
- 時間無重疊、跨午休與隔日、服務時長修改、同時確認等情境應在測試覆蓋。

## 04 預約詳情 `/app/appointments/:id`（桌面抽屜）
任務：同一預約脈絡完成一連串工作。
- 頭部：寵物頭像 52px＋名字、飼主及關聯查看；時間、服務、美容師、價格；重要照護資訊應位於第一屏、無需進二級頁找。
- 獨立區段：預約狀態進度、契約狀態、付款狀態、服務記錄／事件；一次聚焦最主要操作。
- in_service → 點完成美容 → 前端 finish_review 草稿 → 完工時間、正常/異常、選填照片與備註、異常時必填必要紀錄／聯絡狀態、加購須事前確認 → 後端 commit → ready_pickup。
- ready_pickup 頁顯示通知排隊/成功/失敗、應收款、收款與接回分開，未付款交接須授權。
- Mobile：底部主要按鈕不被安全區或軟鍵盤遮住，流程盡量維持同一面板，不用跳五個頁面。
- 結帳有部分付款／退款狀態。不得顯示「LINE 已讀」除非真實取得可靠證據。

## 05 飼主線上預約 `/book/:shopSlug`
任務：四步完成預約申請、不下載 App。
- Mobile：店家識別＋四步進度，步驟一選服務（價格起、預估時間、清楚的單選卡）→二選時段（只有符合業務規則可申請的時段）→三身分與毛孩（既有資料完成安全驗證後帶入，新客簡填）→四確認條款/費用並送出。
- 底部固定一個主要動作（下一步/送出），選項未選時 disabled 並有清楚提示。
- pending 狀態回覆「已收到申請，等待店家確認」，不能顯示「預約成功並保留該時段」。若正式即時確認機制未實作，不做假即時完成動畫。
- Desktop：內容可用 2 欄（步驟和摘要），主流程不要被寬螢幕拉太長。
- 錯誤：時段已被確認占用、身份驗證失敗、網路離線、重複送單；保留合理表單草稿，不顯示假成功。
