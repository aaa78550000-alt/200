# 必須預先考慮的業務邊界案例

1. 一位飼主帶兩隻毛孩：允許同一次申請分別建立每隻毛孩的服務占用、總價與付款關聯；一人多毛孩不可共用錯誤的美容記錄。
2. 同名毛孩 Coco：列表至少顯示照片 + 飼主 + 品種，避免店員誤開。
3. 不確定體重／生日：允許「未提供」，不把缺值顯示為 0 kg 或錯誤年齡。
4. 多員工：一位美容師可能請假、只能服務部分品項、需要休息／緩衝。被確認的舊預約受到新請假影響要標警示，不可靜默刪除。
5. 網路離線：允許查看本機已快取的非敏感 UI 必要信息，但付款、簽約、完工不得離線假成功。
6. 服務中加購：需要飼主確認及費用紀錄。沒有確認不得自動加價。
7. 美容異常：可能需要立即聯繫飼主/獸醫，記錄事件、時間、處理者，不把 AI 生成結論當診斷。
8. 已完工但未付款：仍可待接回；如允許賒帳，要店長確認並記錄。
9. 已付款但毛孩仍在店：待接回，不要變完成。
10. 退款、包套次數回補與帳務更正：以補償交易處理，保留原始事件與操作人。
11. 照片分享：後台可看不代表所有飼主都可看；遵守權限和分享同意。
12. 契約更新：已簽原本的 PDF、hash 和版本仍可取得；新的模板只作用於新服務。
13. LINE 通知：API 回應失敗不得影響主交易；API 成功不等於飼主已讀。
14. 兩個店同一飼主：不能自動連結或跨店洩漏，未來跨店互通需明確授權。
15. 營業時間跨日或臨時公休：時間段與日期以 Asia/Taipei 正確運算，避免 UTC 日期切割 bug。
